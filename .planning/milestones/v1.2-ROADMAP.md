# Milestone v1.2: Internationalization (Italian + French) using next-intl

**Status:** PLANNED 2026-04-30
**Goal:** Add first-class localization with `next-intl`, ship Italian (`it`) and French (`fr`) translations for recruiter-facing portfolio, keep server-first rendering, preserve SEO, and add locale-aware routing and tests.

## Deliverables

- Add `next-intl` dependency and configure TypeScript integration.
- Create `src/i18n` translation loader + typed messages.
- Wrap root `layout.tsx` with `NextIntlProvider` (server) and load locale messages during SSR.
- Provide `public/locales/{en,it,fr}.json` or `src/locales` translation files for all strings.
- Implement language switcher component with server-side navigation and client fallback.
- Update metadata for `hreflang` and localized titles/descriptions.
- Extend Playwright and node tests to verify `en`, `it`, `fr` pages and fallback.

## Phases

- Phase 11: I18N setup (dependencies, loader, provider) - 2 plans
- Phase 12: Translate content keys and files (it, fr) - 3 plans
- Phase 13: Language switcher + SEO integration - 2 plans
- Phase 14: Testing and release verification - 2 plans

## Acceptance Criteria

- `npm run build` passes with `next-intl` integration.
- English `en` remains default and fallbacks to `en` when unknown locale requested.
- `it` and `fr` pages show translated copy for hero, contact, languages, and experience sections.
- Playwright tests confirm localized routes return 200 and correct localized strings.

## Risks

- Next.js experimental app router behavior with i18n — need to follow `next-intl` app-dir examples.
- SEO: ensure hreflang tags and canonical handling correct.
