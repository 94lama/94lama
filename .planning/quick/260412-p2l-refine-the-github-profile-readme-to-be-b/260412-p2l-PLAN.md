# Quick Plan — Refine the GitHub profile README to be brief, captivating, and graphic-heavy

## Objective

Turn the current developer-facing README into a shorter, sharper, more visual GitHub profile: trim the HR-style narration, remove the selected projects block, and replace text weight with GitHub-safe local SVG graphics sourced from `public/assets/cv.json`.

## Context

- `README.md` was already refreshed in quick task `260412-nbj`, but it is still too text-heavy for the new brief.
- `public/assets/cv.json` is the factual source of truth for role, skills, experience, relocation, and contact data.
- The audience is **fellow developers**, not recruiters.
- The user explicitly wants **brief + captivating + graphic-heavy** output, including **skill bars** and a **skill graph**.
- Keep everything GitHub-safe: local assets, markdown, and simple HTML only.

## Task 1 — Create compact GitHub-safe skill graphics from `cv.json`

**Files**
- `public/assets/readme/skill-bars.svg`
- `public/assets/readme/skill-graph.svg`

**Action**
- Create two local SVG assets driven by the actual skills data in `public/assets/cv.json`.
- `skill-bars.svg` should visualize the strongest stack areas with concise labeled bars based on the `knowledge` values already present in the JSON.
- `skill-graph.svg` should provide a second, more graphic overview of the stack mix (for example radar-style, node-map, or categorized graph) while staying simple enough to render reliably on GitHub.
- Keep the visuals factual, restrained, and developer-oriented: no fake metrics, no percentages that are not derivable from the JSON, no badge clutter, no remote dependencies.
- Reuse the existing blue-led README palette so the new assets feel like part of one visual system with `profile-banner.svg`.

**Verify**
- `test -f public/assets/readme/skill-bars.svg && test -f public/assets/readme/skill-graph.svg`
- `node -e "const fs=require('fs'); ['public/assets/readme/skill-bars.svg','public/assets/readme/skill-graph.svg'].forEach(p=>{const s=fs.readFileSync(p,'utf8'); if(!s.includes('<svg')) throw new Error('Missing svg root in '+p);});"`

**Done**
- Two repo-local SVG assets exist, render safely on GitHub, and visualize the CV skill data without inventing claims.

## Task 2 — Rewrite the README to be shorter, peer-facing, and visual-first

**Files**
- `README.md`

**Action**
- Refactor the README around a much tighter narrative: banner, one short positioning block, a compact “current build mode” or equivalent, the new skill graphics, a minimal experience snapshot, and contact links.
- Remove HR-style and culture/collaboration fluff, especially anything that reads like recruiter pitch copy rather than builder-to-builder communication.
- Remove the current `## Selected work` / selected projects style sections entirely; do not replace them with another project catalog.
- Keep experience grounded in `public/assets/cv.json`, but compress it into a lightweight factual snapshot instead of long role-by-role bullets.
- Prefer scan-friendly markdown/simple HTML blocks and image embeds to prose. The README should end up clearly shorter than the current version while still communicating stack, shipped domains, and contact.

**Verify**
- `node -e "const fs=require('fs'); const md=fs.readFileSync('README.md','utf8'); ['profile-banner.svg','skill-bars.svg','skill-graph.svg'].forEach(x=>{if(!md.includes(x)) throw new Error('Missing '+x)}); ['## Selected work','### Nuvolaris','### Aroma S.r.l.','### Loliv','## Working style'].forEach(x=>{if(md.includes(x)) throw new Error('Section should be removed: '+x)}); if(md.length > 2600) throw new Error('README still too long');"`

**Done**
- README is visibly shorter, more graphic-led, and aimed at developers rather than recruiters.
